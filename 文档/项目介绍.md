# 项目介绍:小程序流量监控图表

> 用微信小程序原生框架 + echarts-for-weixin 复刻的一张**可交互流量监控图**(折线面积图),
> 数据为本地 mock,可直接用微信开发者工具打开运行。

## 它实现了什么

以一张「设备上行速率」监控卡片为例(对应需求示例图):

| 功能 | 说明 |
|---|---|
| 监控卡片 UI | 设备标题行(名称/MAC/IP + 统计时段)、指标行(接入带宽 / 当前水位 / 昨日水位) |
| 折线面积图 | 24 小时上行速率,10 分钟一个点共 145 点;蓝色折线 + 渐变面积;Y 轴 0–7 G,X 轴 45° 旋转时间标签 |
| 触摸交互 | 手指按下/滑动出现竖直虚线准线,并弹出 tooltip:时间、`MAC: x.xx G`、参考水位(%) |
| 指标联动 | 「当前水位」「参考水位」均按 `速率 ÷ 接入带宽` 实时推导,不硬编码 |
| mock 数据形态 | 复刻示例图的曲线形状:夜间静默 → 凌晨尖峰 → 回落谷底 → 白天爬升 → 午后骤降回升 → 高位抖动 → 尾部归零 |
| 渲染可验证 | 附带 node 脚本,无 IDE 也能验证图表文字是否越界(见下文「如何运行」) |

## 如何运行

1. 用微信开发者工具「导入项目」选择本仓库根目录(基础库 ≥ 2.9.0 即可,推荐 3.x);
2. 首页即为流量卡片,模拟器或真机上按住图表滑动可体验准线 + tooltip;
3. (可选)命令行执行 `node scripts/verify-render.js` —— 不依赖任何 npm 包,
   用 ECharts SSR 按手机尺寸真实渲染并断言所有文字元素在画布内,输出 `exit 0` 即通过。

## 整体架构

项目分三层,依赖单向,数据流如下:

```
utils/mockTraffic.js          utils/trafficOption.js           components/ec-canvas/
(数据层, 纯函数)       →      (配置层, 声明式 option)    →      (渲染层, 第三方组件)
buildTrafficSeries()          buildChartOption()               echarts.init(canvas)
145 个 {time, value}          数据 → ECharts 配置的翻译表        绘制 + 触摸事件转发
```

```
├── app.json                    全局配置(渲染器为 webview)
├── pages/index/                唯一业务页面: 卡片布局 + 注入 ec 参数
├── components/ec-canvas/       echarts-for-weixin 官方组件(未做任何修改)
├── utils/mockTraffic.js        mock 数据生成器(纯函数, 不依赖 wx)
├── utils/trafficOption.js      ECharts option 构造(纯函数, 不依赖 wx)
├── scripts/verify-render.js    SSR 渲染验证脚本(node 直接跑)
├── 文档/                       本文档 + 开发过程文档
└── CLAUDE.md                   面向后续开发者/AI 协作的工程约定与踩坑记录
```

设计原则:**页面 js 只做「翻译」,不做「绘制」**。数据、配置、渲染各司其职,
交互(准线/tooltip)由 ec-canvas 组件把触摸事件转译给 ECharts 内核,业务代码零参与。

## 对未来开发的兼容性优势

1. **换数据源零侵入**:业务接口只需最终产出 `[{time, value}]` 数组。
   `mockTraffic.js` 是唯一数据出口,接真实 API 时新增一个 request 模块替换它即可,
   配置层与页面完全不动。
2. **配置层可独立演进**:所有视觉与交互(轴、tooltip、面积样式)集中在
   `utils/trafficOption.js` 一处;调样式、换图表类型、增加系列都不触碰数据层。
3. **utils 采用 CommonJS 且不依赖 wx**:因此能被 node 直接 require 复用——
   SSR 验证脚本就是证明。未来做自动化回归(渲染断言、数据形态断言)无需引入小程序环境。
4. **ec-canvas 组件原样保留**:官方上游可随时升级;组件注册制
   (`usingComponents`)让其他页面可直接复用同一图表能力。
5. **mock 生成器是确定性的**(种子伪随机):同一种子永远产出同一曲线,
   便于回归比对与 bug 复现;改造为「读接口 + 降级到 mock」的模式也很自然。

## 当前边界(阅读前须知)

- 数据为**本地 mock**,无任何网络请求;接入真实数据是预期的下一步(见开发过程文档);
- 图表针对**手机窄屏**调校:X 轴刻度为 120 分钟均匀分布(示例图的 80 分钟刻度
  在窄屏会触发标签重叠抑制,详见开发过程文档「取舍」一节);
- tooltip 中的圆点为文本字符(小程序 canvas 模式下 HTML 富文本标记不可靠);
- 仅在开发者工具模拟器验证过,真机(尤其 iOS 高分屏)建议复核一次字体测量差异。
